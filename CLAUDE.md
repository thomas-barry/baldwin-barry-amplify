# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Start Vite dev server (http://localhost:5173)
npm run build        # TypeScript compile (tsc) then Vite bundle → dist/
npm run lint         # ESLint (max-warnings 0, strict)
npm run preview      # Preview production build locally
npm run cleanup      # ⚠️ Destructive: delete all DynamoDB + S3 data
npx ampx sandbox     # Start Amplify sandbox (generates amplify_outputs.json)
```

Use **npm** only — not pnpm or yarn.

To type-check without building: `npx tsc --noEmit`

To auto-fix lint issues: `npm run lint -- --fix`

There are no automated tests. Verification is manual in the browser.

## Architecture

**Frontend**: React 18 + TypeScript (strict) + Vite 7. Routing via **Tanstack Router** (file-based, `src/routes/`). Server state via **Tanstack Query** v5. UI via **PrimeReact** + **PrimeFlex** utility classes. CSS via **CSS Modules** + Lightning CSS transformer.

**Backend**: AWS Amplify Gen 2 — Cognito (auth), DynamoDB via AppSync GraphQL (data), S3 (storage), Lambda (functions). Backend is defined in `amplify/` which has its own `package.json` and `node_modules`.

### Critical: amplify_outputs.json

`amplify_outputs.json` (git-ignored) is imported directly in `src/main.tsx` and **must exist** or the build fails. Generate it by running `npx ampx sandbox`. For CI/type-check-only, create a minimal mock:
```json
{ "version": "1", "auth": {}, "data": {}, "storage": {} }
```

### Data Schema (`amplify/data/resource.ts`)

Three DynamoDB models via AppSync GraphQL:
- **Gallery** — name, description, createdDate, thumbnailImageId → has many GalleryImages
- **Image** — title, s3Key, s3ThumbnailKey, EXIF data, dimensions → has many GalleryImages
- **GalleryImage** — join table linking Gallery ↔ Image with order and addedDate

Authorization: public API key for reads; Cognito `admin` group for mutations.

### Lambda: `onUploadHandler`

Triggered on S3 upload events. Receives `GRAPHQL_ENDPOINT`, `GALLERY_TABLE_NAME`, `IMAGE_TABLE_NAME`, `GALLERY_IMAGE_TABLE_NAME` as environment variables. Has direct DynamoDB table access (bypasses AppSync). Defined in `amplify/functions/onUploadHandler/`.

### Auth Flow

Custom `AuthContext` (`src/context/AuthContext.tsx`) wraps Cognito via `aws-amplify/auth`. Exposes `isAuthenticated`, `isAdmin` (checked via `cognito:groups` claim), `username`, `login()`, `logout()`. Use `useAuth()` hook to consume. Admin status gates write operations.

### Path Aliases

Always use path aliases for cross-directory imports:
- `@/components/*`, `@/modules/*`, `@/context/*`, `@/lib/*`, `@/assets/*`, `@/routes/*`
- `@/*` → `src/*`

### Routing

File-based routes in `src/routes/`. `src/routeTree.gen.ts` is auto-generated by Vite plugin — **never edit manually**. Dynamic route params use `$param.tsx` naming.

### Conventions

- Functional components only; no class components
- CSS Modules for all component styles (co-located `.module.css` file)
- Tanstack Query for all server state — never fetch directly in components; never use local state for server data
- Interfaces over type aliases for object shapes; no `any` — use `unknown` or proper types
- `import type` for type-only imports
- Naming: PascalCase components/interfaces/CSS modules, camelCase functions/variables, ALL_CAPS constants
- New components: create folder `src/components/MyComponent/` with `MyComponent.tsx`, `MyComponent.module.css`, `index.ts`
